# Регламент Обновления Документации

Документация должна отражать фактическое состояние проекта. Если код и схема расходятся, сначала фиксируется реальность, затем отдельно планируется улучшение.

## Еженедельная Проверка

1. Проверить структуру файлов через `rg --files`.
2. Сверить `index.html` со списком подключённых CSS/JS/assets.
3. Сверить `app.js` с моделью `prepbase-mvp-v2`.
4. Сверить `knowledge-ui.js` и `knowledge-tree.js` с описанием дерева знаний.
5. Сверить `questions-extra.js` с миграцией вопросов.
6. Проверить `.github/workflows/update-skills-stats.yml` и `scripts/parse-job-sites-skills.js`.
7. Обновить Mermaid-диаграммы в `docs/architecture.md` и `docs/data-model.md`.
8. Обновить таблицу статуса в `docs/README.md`.
9. Если менялись пользовательские сценарии, обновить основной `README.md`.

## Definition Of Done

- Диаграммы открываются в GitHub Markdown.
- В документации нет несуществующих модулей, API или БД.
- Указано, какие контуры активны, а какие подготовлены, но скрыты.
- Новые файлы и ключи `localStorage` отражены в `docs/data-model.md`.
- Если изменён deployment или GitHub Actions, это отражено в `docs/architecture.md`.

## Когда Обновлять Вне Расписания

- Добавлен новый раздел приложения.
- Изменился формат `localStorage`.
- Появился backend/API.
- Изменился формат `skills-stats.js`.
- Включили или отключили вакансийную аналитику.
- Изменился deployment GitHub Pages.
